## Database authorization

All exposed tables require RLS and explicit grants. Determine identity from auth.uid(); role/status must come from protected account rows, never client input or editable auth metadata. Inactive/setup_pending/anonymous identities cannot access helpdesk records or mutate data. A minimal self-status response may be designed for future account routing; document it and reveal no ticket information.

| Capability | Admin | Primary technician | Collaborator | Unrelated technician |
| --- | --- | --- | --- | --- |
| Read ticket and all its child records | All | Own | Participating | Only unowned Open tickets |
| Create ticket | Any channel, optional active owner | Walk-in, self-owned | Same technician intake rule | Same technician intake rule |
| Claim | Unowned Open only | Unowned Open only | Unowned Open only | Unowned Open only |
| Add notes/device observations, change priority/progress | Active tickets | Active owned | Active participating | No |
| Resolve with solution, no time requirement | Yes | Yes | Yes | No |
| Manage collaborators | Yes | Yes, active owned | No | No |
| Return unfinished work to Open Queue | Yes | Yes | No | No |
| Reassign to another owner, reopen/cancel with reason | Yes | No | No | No |
| Log own optional time | Visible noncancelled work per domain rules | Owned, including resolved | Participating, including resolved | No |
| Account role/status administration | Protected admin boundary | No | No | No |

Technicians may read minimal active-account labels needed to select collaborators and resolve historical attribution; do not expose the full administration/email/credential metadata through that lookup. Minimal requester lookup must support technician walk-in intake; document allowed fields separately from ticket visibility. This is not access to a future full student/staff directory.

Protect tables and RPCs against direct REST writes, forged authors/owners/roles/timestamps, fabricated activity, and unsafe deletes. Prefer narrowly granted mutation RPCs with public table writes revoked. Ensure every RPC independently checks identity, authorization, current state, and input. Audit events are written in the same transaction as their mutation and cannot be edited by users. Security-definer helpers require a fixed safe search_path, qualified references, minimal EXECUTE grants, and protection against helper-based visibility leaks and recursive RLS policies. Views must not bypass RLS.

Port the currently implemented ticket actions: intake, claim, reassign/return, collaborators, notes, device observations, priority, progress/waiting, time logging, resolve, reopen, cancel. ## Transactions and history

- Claim must allow exactly one winner across concurrent authenticated connections.
- Resolution requires a trimmed solution of at least the current domain minimum; owner remains unchanged, resolver/time recorded separately, one completion event per resolution cycle. Reopen then re-resolve is valid and retains earlier history.
- Return clears current ownership/assignment time/waiting state, sets Open, preserves collaborators, notes, devices, logs, previous solution and history, and records the returning actor/prior owner. Another technician may claim. Former owner then loses access unless still a collaborator; past authorship is not a grant of access.
- Serialize lifecycle/contribution operations consistently (e.g. lock parent ticket before checking state) so claim/return, resolve/return, resolve/note, collaborator removal/contribution, and deactivation cannot authorize stale writes or lose history. Avoid deadlocks through a consistent lock order.
- Do not expose another ticket's owner through an arbitrary-id failed claim. For M2 use a generic unavailable/already claimed result unless an actually scoped, tested prior-visibility mechanism exists. Document this deliberate privacy-safe adjustment to the demo's owner-naming race message; M3 must use the backend contract.

2. Queue, owned, collaborating, closed history, counts/search, direct ticket ids, and each child table obey visibility. Unrelated/inactive/setup_pending/anonymous reads leak no ticket or contribution data.
3. Direct table and RPC attempts cannot elevate roles, forge ownership/authorship/time, create fabricated events, alter protected fields, or delete history. Missing and invisible ids have equivalent unavailable behavior.
4. Admin intake defaults open/unassigned, assignment/backdating retains actual creation time; technician intake is walk-in/self-owned/today and rejects spoofed fields.
5. Owner and collaborator resolution succeeds with no time; blank/trivial solution fails; original owner, contributor attribution, missing-time semantics and historical solution events survive lifecycle changes.
6. Assigned/In Progress/Waiting return preserves all contributions and collaborators, appears in Open Queue, can be reclaimed, revokes prior owner's later access appropriately. Collaborator/unrelated/inactive/closed-ticket return and technician reassignment to another owner fail.
7. Collaborator removal and account deactivation immediately revoke access with an existing authenticated session, preserving history. Active work remains visible to admin for reassignment.
8. Concurrent calls over separate sessions/connections: two claims, two resolutions, resolve versus return, and a contribution versus closing/removal. Assert exactly the allowed final state, no lost records/duplicate events, and no partial mutation after failure. Use real competing calls, not sequential calls described as concurrency.
9. Minimal requester/account lookup returns only its documented fields; no administration metadata leaks. Reopen/cancel require reasons and preserve previous events.
